# Browser distribution

The NSIS installer registers the same bounded Native Messaging host for Chrome, Edge, Brave, Chromium and Firefox under the current user's account. Repeated installation and runtime repair replace only Flux's manifest values; uninstallation removes registrations owned by the installed executable. Browser cookies and download history remain in the browser profile.

Chromium host manifests contain `allowed_origins`; Firefox uses `allowed_extensions` and the stable `flux@flux-download.local` identity. The host independently checks launcher arguments before reading its four-byte framed input. Chromium store IDs can differ: put the approved IDs in `native-host/chromium-extension-ids.json` before building the desktop release. The shared unpacked extension ID remains included. Do not put OAuth credentials or Mozilla signing tokens in this file.

Run `./scripts/package-browser-stores.ps1` to create runtime-only Chrome, Edge and Firefox store ZIPs, then `./scripts/verify-browser-stores.ps1` to verify their exact file set and source hashes. Chrome and Brave use the Chrome Web Store distribution; Edge can use its own reviewed store listing or the Chrome Web Store version. The `Prepare browser store packages` workflow validates the production Gecko manifest and prepares the same ZIPs. It can request an unlisted Mozilla signed XPI when explicitly enabled with repository secrets `AMO_JWT_ISSUER` and `AMO_JWT_SECRET`.

Normal Windows Chrome installations require a Web Store listing for consumer installation without developer mode. Standard Firefox requires Mozilla signing for permanent installation. Store publication and signing depend on the account's permissions and review; the application does not bypass these checks or force browser enterprise policies. Native host registration is automatic once the application is installed. The prepared local ZIPs have no store signature.

The Firefox 140+ package declares authentication, browsing and website content transfer for its local desktop integration. Firefox 120–139 uses explicit native-transfer consent in its settings and a DOM/network fallback where MAIN-world script injection is unavailable. The modern manifest declares Firefox for Android 142 as its minimum schema version; the distributed desktop host and installation tests target Windows x64.

## Privacy disclosure for store listings

Flux detects media requests and media elements on HTTP(S) pages. Native transfer is initiated by a user action or an enabled download interception preference. The extension shares selected source URLs, titles, format metadata and origin-scoped session credentials with the local Flux application. Firefox local transfer requires consent. Request headers are kept in session storage, durable transfers use protected credentials, and public task responses omit authentication secrets. There is no analytics endpoint or remote Flux account. Downloading media contacts the selected source's servers and, for torrents, the swarm, trackers and DHT. Torrent completion stops sharing rather than running an unrequested background seed process.

Sources: [Chrome Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging), [Edge Native Messaging](https://learn.microsoft.com/en-us/microsoft-edge/extensions/developer-guide/native-messaging), [Mozilla signing and distribution](https://extensionworkshop.com/documentation/publish/signing-and-distribution-overview/).
