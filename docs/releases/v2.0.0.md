# Flux 2.0.0

This major upgrade adds an embedded BitTorrent transfer path and removes HTTP chunk concatenation. The same persistent queue, approval windows, scheduling, history and progress surfaces manage HTTP, adaptive media and torrent downloads.

## Transfer engine

HTTP workers write disjoint byte ranges to one destination-volume staging file. Windows uses sparse allocation without privileged `SetFileValidData`; Linux uses fallocate with a safe length-only fallback on unsupported filesystems. Rolling per-range SHA-256 checkpoints survive pause and retry. A resumed task verifies its recorded prefixes, and legacy chunk files migrate without losing their verified bytes. One sequential integrity pass checks every range and calculates the final SHA-256 before exclusive publication. Completion is displayed only after verification; pre-existing user files are preserved.

The embedded `librqbit = 9.0.1` engine uses Tokio and rustls. It accepts BitTorrent v1/hybrid magnets, HTTP(S) torrent metadata and explicit local .torrent imports, supports DHT/tracker/peer discovery and standard piece checks, exposes file selection and peer counts, and applies task-specific download/upload shaping. HTTP, adaptive media and torrent tasks share the configured global bandwidth budget. Restart rechecks native pieces and repairs corrupted bytes. Selected files receive individual SHA-256 digests. Removing a task preserves its downloaded user files. Completion stops the managed torrent rather than silently starting a seed service.

## Browser and media

The shared Chromium and Gecko implementation observes media elements, source/track changes and per-frame network requests. Modern MAIN-world hints identify audio/video Blob and MediaSource types; the Gecko 120 path keeps DOM/network capture. Standalone inaccessible blob data is not mislabeled as an HTTP file.

Asynchronous metadata resolves real titles, one quality choice per resolution, frame rates, audio tracks and subtitles for supported providers. Provider cookies are scoped to the selected origin in a private temporary cookie jar. Playlist, channel and captured-page batches persist task UUIDs before transfer and feed the desktop queue without opening hundreds of approval windows. The durable outbox has bounded entry count and total metadata size; failed writes cannot partially persist a batch.

Expired HTTP 401/403/410 sources ask the original browser page for current DOM/network sources and origin cookies. The extension does not reload, seek, create or focus tabs. Unchanged content validators permit resuming the verified offset; closed pages, changed content and access-denied sources produce explicit errors.

## Desktop and installation

Separate native windows add torrent import, collection pagination and virtualized torrent file selection. Settings retain automatic connection counts, twenty languages and Arabic/Urdu RTL. Progress stays below 100 percent until verified completion. Metadata work and disk verification run away from the native UI event loop.

Per-user host binding covers Chrome, Edge, Brave, Chromium and Firefox on install, runtime repair and uninstall. Store-ready ZIP preparation and an explicit Mozilla signing workflow accompany the existing SignPath application signing pipeline. A normal consumer browser still requires its store listing or Mozilla signature; the application does not override enterprise policies or browser signing checks.

Packaging disables Tauri's bundle-type binary patch because Flux does not use a per-package updater. Installer and portable executable hashes must therefore match exactly, and a pre-existing executable signature remains intact. The installer harness checks all nine bundled executable/library hashes before integration tests. See the [Tauri bundler release note](https://tauri.app/release/tauri-bundler/v2.10.0/).

## Scope

Windows x64 packages include the pinned LGPL FFmpeg runtime, Node and yt-dlp with complete license inventories and matching media sources. Flux source remains MIT; librqbit is Apache-2.0. The native BitTorrent engine currently rejects v2-only metainfo. Its governor quotas require a per-task limit of 0 or at least 16 KiB/s; the shared limit must be 0 or at least 32 KiB/s while torrents are active.

DRM, CAPTCHA, provider login challenges and opaque streams without an accessible network source remain source access constraints. Validation covers the checked fixtures and local machines. Comparative superiority over IDM, FDM, JDownloader or Motrix requires a separate reproducible benchmark against those applications.
