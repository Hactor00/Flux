# Flux 1.7.0 validation

The original Windows 1.7 baseline passed 82 Rust tests, 32 extension tests and six UI data tests. The 13 October HUD repair expanded the extension suite to 39 tests; all 39 extension and six UI data tests passed again. The release record combines those 45 fresh frontend results with the unchanged 82-test core baseline, for 127 recorded automated results. It preserves individual evidence timestamps rather than presenting the core baseline as a new run. Strict Clippy, Rust formatting and the production dependency audit passed in the baseline; TypeScript and the Vite production build passed again with the repair.

The rebuilt installer passed its native Windows suite, and Firefox 120/157 passed again with the repaired bundled sources. Chrome 154 validated real viewport-wide dragging and unclipped panel geometry with a controlled bridge fixture. See the [HUD repair scope](validation-hud-1.7.md) for reproduction commands and the distinction between browser rendering and external provider tests.

Real Firefox 120.0 and 157.0.1 were tested with isolated profiles and the installed extension files. Both passed native stdio framing, Firefox caller authorization, captured-cookie protection and authenticated downloads with SHA-256 verification. Browser downloads were paused, proposed to the desktop and cancelled after durable acceptance. The local transfer consent, actual site-permission prompt where needed, permission withdrawal and registry restoration were verified.

Both Gecko HUD paths passed closed-shadow isolation, a page CSP that disallows page styles and connections, outside-click dismissal, keyboard placement, real pointer dragging, viewport resizing, fullscreen-container placement and the close button. Firefox 120 used the fixed overlay; Firefox 157 used the native popover API.

The NSIS installation included all three extension directories and the pinned media/runtime tools. Installed JavaScript and manifests matched the validated sources. All four Native Messaging registry entries were checked. Repeated registration, repeated unregister and repair after removal succeeded. Uninstall retained user data and removed owned startup and browser registrations, then the harness restored the original registry state.

The installed desktop passed 20 concurrent native requests, nine downloads, active shutdown/resume, native 32-connection approval, four separate details-window lifecycles, automatic defaults, timestamp display and adaptive media progress/ETA. A delayed settings race discovered by the window test was fixed: proposal connections initialize directly, and later settings cannot overwrite a user's connection choice. Existing daily-use checks, including cancelling completion actions and exiting after the countdown, passed.

Mozilla web-ext 10.7.0 reported no errors or notices for the modern manifest. Its single warning concerns Firefox for Android 140 lacking the newer data declaration. This release targets Windows desktop; Android and non-Windows native installation were not verified. Mozilla signing and AMO publication were not performed. The Firefox ZIPs are unsigned development packages; permanent release-channel installation requires a Mozilla-signed XPI.

Physical sleep, hibernation, power-off and drag-and-drop into third-party programs were not executed. External YouTube behavior was not repeated. Functional browser checks do not constitute a general performance equivalence benchmark. Detailed results and tested installer/binary SHA-256 values are recorded in `docs/validation/release.json`.
