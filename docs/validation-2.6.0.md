# Flux 2.6.0 validation

Release validation must cover the actual packaged Windows installer/portable executables, Fedora RPM, both Firefox identities, the existing Chromium identities, source inspection, saving a torrent metadata file without starting its contents, local video preview, portable path relocation and the signed updater.

The version-specific report is generated by the release workflows in `docs/validation/release.json` inside the source archive. `release-info.json` identifies the source commit and successful Windows/Linux workflow runs. Earlier reports are historical and are not evidence for 2.6.0.

Store submissions have a separate approval lifecycle. An accepted upload is not evidence that an extension is publicly available. The matching runtime/source ZIPs and publisher records are kept separately from public user downloads.
