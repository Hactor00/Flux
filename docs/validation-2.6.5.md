# Flux 2.6.5 validation

The version-specific machine-readable report is generated by release workflows in `docs/validation/release.json` inside the source archive. `release-info.json` identifies the successful Windows and Linux workflow runs and source commit. Earlier records remain historical; they do not prove this release passed.

Required checks include localization parity for all 20 catalogs, frontend/extension regressions, native browser identities, download size/completion/selection behavior, Rust tests and Clippy, installed Windows upgrade preservation, signed updater artifacts and installed Fedora RPM behavior. Desktop statistics tests cover consent defaults, seven/45-day reminders, permanent suppression, withdrawal and disabled-network behavior. PHP tests exercise daily/weekly deduplication, validation, 35-day retention, deletion, HMAC storage, one-time setup, CSRF and private login.

The separate website package is checked locally across its 20 languages. The statistics service is not deployed by release automation; the operator must install the private package before collection begins. Installer language selection has 20 entries; uncommon maintenance messages can fall back to English. Linux package-manager UI languages are outside Flux's installer control.
